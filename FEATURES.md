# Features

Numbered register of every feature an operator or user of the images sees; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md).

- **F1 — Two headless images.** `mwaeckerlin/nextcloud:nginx` serves the web frontend, `mwaeckerlin/nextcloud:php-fpm` runs Nextcloud; neither image carries a shell, bash, busybox or perl. The `nginx` image carries only what a browser requests: no PHP code, no source maps, no sample files of new users. The `php-fpm` image carries no source maps, and its JavaScript and CSS are empty files.
- **F2 — Unattended installation.** On the first start Nextcloud installs itself against MariaDB, with the database and admin passwords read from Docker secrets, and needs no browser step.
- **F3 — Office works out of the box.** The office app `richdocuments` is installed and configured against Collabora, and a document uploaded over WebDAV opens in the office editor. Collabora is the only office app: the start disables ONLYOFFICE, which claims the same file types.
- **F4 — WebSocket apps without nginx changes.** A request to `/ws/<appid>/<path>` reaches the service `<appid>-ws` on port 3001 with the path and query string after `/ws/<appid>`.
- **F5 — One tag per Nextcloud major version.** Branch `new-NN` publishes `nginx-ncNN`, `php-fpm-ncNN` and `notify-push-ncNN`, and its `php-fpm` image carries exactly Nextcloud `NN`, so an installation can step through the major versions one at a time. Every push to `new` also rebuilds `new-33` to `new-35` from the pushed commit, so every major version carries the version just pushed. The branches `new-30` to `new-32` are frozen, because Nextcloud 30 to 32 refuse the PHP 8.5 of the base image.
- **F6 — Published for amd64 and arm64 with date and version tags.** Every push builds the images natively for both architectures and publishes them under their tag, the day of the build and the version with a leading `v` (`nginx-nc35-v1.1.15`, `nginx-v1.1.15`, each also with the date), with the reusable workflow of `mwaeckerlin/scratch`, and so does the hourly check once a parent image or a download changed or the image is a week old. The images are `nginx`, `php-fpm` and `notify-push`.
- **F7 — Bounded database connections.** At most `MAX_REQUEST_WORKERS` PHP processes answer at the same time, 100 by default, so Nextcloud stays below the default connection limit of the database and needs no root password for it.
- **F8 — Health check without configuration.** The `php-fpm` image reports healthy, as the legacy image does, once php-fpm answers `status.php` and Nextcloud is installed, not in maintenance mode and needs no database upgrade; `nginx` starts only after `php-fpm` is healthy.
- **F9 — The variables of the legacy image.** A compose file of the legacy image `mwaeckerlin/nextcloud:latest` keeps working: `UPLOAD_MAX_FILESIZE`, `MEMORY_LIMIT`, `MAX_INPUT_TIME`, `MAX_REQUEST_WORKERS`, `WAIT_SECONDS_FOR_MYSQL`, `URL` beside `HOST`, `PROTOCOL`, `WEBROOT`, `DEBUG`, `ADMIN_USER`, `ADMIN_PWD`, `MYSQL_*` and `MYSQL_ENV_MYSQL_*` carry the same names, defaults and effect.
- **F10 — Upgrade on start and background jobs.** As in the legacy image, every start of an installed Nextcloud leaves maintenance mode, upgrades, repairs and completes the database, and background jobs run by cron every 15 minutes with a daily file scan.
- **F11 — Integrity check active on a reduced release.** The build signs core and the shipped apps again with a CA of its own beside the Nextcloud CA, so Administration settings › Overview reports no integrity error, apps from the App Store still verify against the Nextcloud CA, and a changed file is reported.
- **F12 — Mail server from the stack, the administrator or a variable.** Nextcloud mails over `smtp-relay:25` by default. An external server with login (own Postfix, SendGrid, Gmail) is set under Administration settings › Basic settings and stays in effect, also from a legacy image, or by `MAIL_SMTPHOST`, `MAIL_SMTPPORT`, `MAIL_SMTPSECURE`, `MAIL_SMTPNAME` and the secret `nextcloud_smtp_password`, which take precedence.
- **F13 — Administration pages without warnings.** Administration settings › Overview reports no error and no warning that the images can settle: an old installation gets its missing optional indices and its tables in `ROW_FORMAT=DYNAMIC` while it runs, the source map test file is served, OPcache has room for interned strings, and every container has a server ID. Nextcloud trusts the private networks of Docker as proxies, locks files in Redis, keeps a log file for Administration settings › Logging below `LOG_MAX_SIZE` and passes every line on to the container log, and every start writes the setup checks that remain into the container log. On MySQL every start warns while the account of Nextcloud still logs in with `mysql_native_password`, which MySQL 9 removes. Nextcloud Office accepts WOPI requests only from the private networks of Docker, so its page shows no warning either. The README lists the services outside the images that the remaining checks need.
- **F14 — Client Push.** The image `mwaeckerlin/nextcloud:notify-push` runs the push server of the app `notify_push`; with `NOTIFY_PUSH_HOST` the start installs the app, `nginx` forwards `/push/` to the push server, and the self-test of the app passes.
- **F15 — Talk high-performance backend.** `docker-compose.talk.yml` adds a signaling server and NATS; with `TALK_SIGNALING_HOST` the start installs Talk and registers the signaling server with a secret that never stands on a command line, `nginx` forwards `/standalone-signaling/` to it, and the admin overview reports no error about the high-performance backend.
