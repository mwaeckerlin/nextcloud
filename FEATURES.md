# Features

Numbered register of every feature an operator or user of the images sees; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md).

- **F1 — Two headless images.** `mwaeckerlin/nextcloud:nginx` serves the web frontend, `mwaeckerlin/nextcloud:php-fpm` runs Nextcloud; neither image carries a shell, bash, busybox or perl. The `nginx` image carries only what a browser requests: no PHP code, no source maps, no sample files of new users. The `php-fpm` image carries no source maps, and its JavaScript and CSS are empty files.
- **F2 — Unattended installation.** On the first start Nextcloud installs itself against MariaDB, with the database and admin passwords read from Docker secrets, and needs no browser step.
- **F3 — Office works out of the box.** The office app `richdocuments` is installed and configured against Collabora, and a document uploaded over WebDAV opens in the office editor.
- **F4 — WebSocket apps without nginx changes.** A request to `/ws/<appid>/<path>` reaches the service `<appid>-ws` on port 3001 with the path and query string after `/ws/<appid>`.
- **F5 — One tag per Nextcloud major version.** Branch `new-NN` publishes `nginx-NN` and `php-fpm-NN`, and its `php-fpm` image carries exactly Nextcloud `NN`, so an installation can step through the major versions one at a time. The branches `new-30` to `new-32` are frozen, because Nextcloud 30 to 32 refuse the PHP 8.5 of the base image.
- **F6 — Published for amd64 and arm64 with date and version tags.** Every push and every Monday builds the images natively for both architectures and publishes them under their tag, the day of the build and the version, with the reusable workflow of `mwaeckerlin/scratch`.
- **F7 — Bounded database connections.** At most `MAX_REQUEST_WORKERS` PHP processes answer at the same time, 100 by default, so Nextcloud stays below the default connection limit of the database and needs no root password for it.
- **F8 — Health check without configuration.** The `php-fpm` image reports healthy, as the legacy image does, once php-fpm answers `status.php` and Nextcloud is installed, not in maintenance mode and needs no database upgrade; `nginx` starts only after `php-fpm` is healthy.
- **F9 — The variables of the legacy image.** A compose file of the legacy image `mwaeckerlin/nextcloud:latest` keeps working: `UPLOAD_MAX_FILESIZE`, `MEMORY_LIMIT`, `MAX_INPUT_TIME`, `MAX_REQUEST_WORKERS`, `WAIT_SECONDS_FOR_MYSQL`, `URL` beside `HOST`, `PROTOCOL`, `WEBROOT`, `DEBUG`, `ADMIN_USER`, `ADMIN_PWD`, `MYSQL_*` and `MYSQL_ENV_MYSQL_*` carry the same names, defaults and effect.
- **F10 — Upgrade on start and background jobs.** As in the legacy image, every start of an installed Nextcloud leaves maintenance mode, upgrades, repairs and completes the database, and background jobs run by cron every 15 minutes with a daily file scan.
- **F11 — Integrity check active on a reduced release.** The build signs core and the shipped apps again with a CA of its own beside the Nextcloud CA, so Administration settings › Overview reports no integrity error, apps from the App Store still verify against the Nextcloud CA, and a changed file is reported.
- **F12 — Mail server from the stack, the administrator or a variable.** Nextcloud mails over `smtp-relay:25` by default. An external server with login (own Postfix, SendGrid, Gmail) is set under Administration settings › Basic settings and stays in effect, also from a legacy image, or by `MAIL_SMTPHOST`, `MAIL_SMTPPORT`, `MAIL_SMTPSECURE`, `MAIL_SMTPNAME` and the secret `nextcloud_smtp_password`, which take precedence.
